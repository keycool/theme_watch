# 急跌读数规格 v1（观察层 · 候选）

> **状态：候选规格，未接入生产。** 依据 2026-09-22《急跌形态研究记录 v1.0（存档）》，
> 由客户甲拍板走「方向 A」：只做**纯几何观察读数**，不提炼特征值、不出任何交易条件。
> 接入前需要经过客户甲确认，并另行排期。

---

## 1. 定位：它是「Series A 的第三只读数」

观察层现有两只跟"跌"有关的读数，本读数是第三只，**视角不同，互不替代**：

| 读数 | 视角 | 窗口 | 阈值 | 回答的问题 |
| --- | --- | --- | --- | --- |
| `market_context.declineRegime` | **横截面**（我跟别人比） | 5 日 | −3% | 这次跌是全市场一起跌，还是单独砸我？ |
| **`drawdown`** | **时序**（我跟自己比） | 20 日 | −10% | 我自己从高点掉下来多深、用了几天、怎么掉的？ |
| `all_topics` 的均线读数 | 位置 | 20/60/250 | — | 我在均线系统的哪个位置？ |

**三者可以并存于同一份 topic 的 `summary.observation` 下**，互不覆盖：
```jsonc
"observation": {
  "context": { ... },      // market_context（横截面）
  "drawdown": { ... },     // 本读数（时序）
  "stateCode": "..."       // 均线位置
}
```

⚠️ **窗口不一致，禁止混用**：`market_context` 是 5 日、`drawdown` 是 20 日。
两者的百分数**不可直接相减或换算**，引用时必须连 `windowDays` 一起引用。

## 2. 三条使用禁令（来自存档研究，是本规格的一部分）

这三条不是建议，是**该读数的成立前提**。违反任何一条，这个读数就变成误导。

### 禁令一：禁止事后确认底部
研究报告 §2 实测：无前视口径下后 20 日收益中位数 **+0.54%**（45% 为负）；
一旦允许"后 3 日不再创新低"的事后确认，就跳到 **+6.03%**。
**差的 5.5pp 全部来自未来信息。**

→ 因此本读数**每个交易日都输出当前状态**，不存在"确认低点"的动作。
→ 任何下游都**不许**用「后面几天没创新低」去回填式地改写历史读数。

### 禁令二：禁止把「触发」当成「到底了」
实测触发之后还要继续跌：**中位数再跌 1.64%**，47% 概率再跌 2% 以上，22% 概率再跌 5% 以上。

→ `triggered: true` **只表示"回撤到了这个深度"**，不表示跌完了。
→ 读数字段里**不存在**任何"是否见底 / 是否安全 / 是否值得买"的字段。

### 禁令三：禁止用本读数的字段做筛选条件
实测全部形态特征（跌幅/跌法/量能/波动/连跌天数）的三分位区分力只有 **3~8pp**，
且**几乎全部不单调**——非单调的分层就是噪音。

唯一的例外是「离 MA60 距离」（见 §5 的边缘条款）。

## 3. 几何定义（精确到可复算）

**回撤窗口** `windowDays = 20`（交易日）
**触发阈值** `thresholdPct = -10.0`（百分数，含等于）

对每一个交易日 `t`：

1. 取 `t`（含）往前 `windowDays` 个交易日的**收盘价序列** `[c(t-19) ... c(t)]`。
2. `peakClose` = 该序列的最大值；`peakDate` = 其所在日期。
   - **并列取最早**（保证 `peakDate` 稳定，不会因未来一根同价 K 线而移动）。
3. `drawdownPct = (c(t) / peakClose - 1) × 100`。
4. `triggered = drawdownPct <= thresholdPct`。
5. `drawdownDays` = 从 `peakDate` 到 `t` 的**交易日个数**（不含起点，含终点）。

**关键：这是一个每个交易日刷新的状态量，不是事件。**
不存在"事件开始/结束"，也不做任何去重、合并、窗口跳跃。

> ⚠️ **实现坑（实测踩过，勿删）**
> 「含等于」不能靠 `dd <= thresholdPct` 直接判断：`9.0/10.0-1` 在浮点下是
> `-0.09999999999999998`，乘 100 后 `-9.999999999999998`，恰好 −10% 会被判成 False。
> 参考实现用 `dd <= thresholdPct + 1e-9` 处理。

## 4. 字段表

```jsonc
"drawdown": {
  "schemaVersion": "1.0",
  "asOf": "2026-09-22",

  // —— 核心几何 ——
  "triggered": false,
  "windowDays": 20,
  "thresholdPct": -10.0,
  "drawdownPct": -4.12,
  "peakDate": "2026-09-08",
  "peakClose": 3.618,
  "drawdownDays": 10,

  // —— 跌法（纯描述，不参与判断）——
  "maxSingleDayDropPct": -3.21,
  "downDaysOver2Pct": 2,
  "downDaysOver3Pct": 1,
  "upDaysRatio": 0.40,
  "maxConsecutiveDownDays": 3,

  // —— 量能与波动 ——
  "volumeRatio": 1.24,
  "volatilityRatio": 1.08,

  // —— 位置 ——
  "ma20GapPct": -3.55,
  "ma60GapPct": -6.12,

  // —— 同期基准（窗口与 market_context 不同，禁止混用）——
  "marketRetPct": -1.88,
  "excessPct": -2.24,

  // —— 固定声明 ——
  "decisionUse": false,
  "note": "纯几何读数：描述过去 20 个交易日内从最高收盘到当前的回撤结构与跌法，不含买卖含义。"
}
```

| 字段 | 类型 | 定义 | 空值条件 |
| --- | --- | --- | --- |
| `triggered` | bool | `drawdownPct <= thresholdPct` | 无 |
| `drawdownPct` | float\|null | 当前收盘相对 `peakClose` 的回撤% | 数据不足 2 根时 null |
| `peakDate` | string\|null | 窗口内最高收盘日（并列取最早） | 同上 |
| `drawdownDays` | int | 峰值日到当前日的交易日数 | 同上 |
| `maxSingleDayDropPct` | float\|null | 峰值→当前区间内最大单日跌幅% | 区间不足 2 根时 null |
| `downDaysOver2Pct` | int | 区间内单日跌幅 ≤ −2% 的天数 | 0 |
| `downDaysOver3Pct` | int | 区间内单日跌幅 ≤ −3% 的天数 | 0 |
| `upDaysRatio` | float\|null | 区间内上涨天数 / 区间总天数 | 区间不足 2 根时 null |
| `maxConsecutiveDownDays` | int | 区间内最大连续下跌（按收盘）天数 | 0 |
| `volumeRatio` | float\|null | 区间日均成交量 / 峰值日前 20 日均量 | 前者缺时 null |
| `volatilityRatio` | float\|null | 区间日收益标准差 / 峰值日前 20 日标准差 | 前者缺时 null |
| `ma20GapPct` | float\|null | 当前收盘 / MA20 − 1（%） | MA20 未成形时 null |
| `ma60GapPct` | float\|null | 当前收盘 / MA60 − 1（%） | MA60 未成形时 null |
| `marketRetPct` | float\|null | 同区间基准（沪深300）涨跌% | 缺基准时 null |
| `excessPct` | float\|null | `drawdownPct − marketRetPct` | 任一为 null 时 null |

## 5. 边缘条款：唯一允许被"注意"的字段

`ma60GapPct` 是研究里**唯一单调且极差最大**的特征，但它**不能写成信号**，只能写成说明：

| 离 MA60 三分位 | 后 20 日收益中位数（存档研究，样本内） |
| --- | --- |
| 低（尚在 MA60 附近） | +8.12% |
| 中 | −0.53% |
| 高（深度跌破 MA60） | −9.25% |

→ **方向是趋势延续，不是均值回归。** 若被引用，正确的表述是
「深度跌破 MA60 的标的，后续继续下跌的概率更高」，**绝不是**「跌深了可以抄」。
→ 该数字**未做样本外验证**，是从同一批样本里挑出来的，有过拟合风险。
→ 引入 downstream 前必须先换时间段/标的池复算。

## 6. 边界情况处理

| 情况 | 处理 |
| --- | --- |
| 上市不足 20 个交易日 | 按实际根数计算，`windowDays` 输出实际值；不足 2 根时整组字段为 null |
| 停牌/缺失交易日 | 按**已存在的 K 线根数**计为交易日，不插值、不 forward-fill 价格 |
| 除权除息 | 统一使用**前复权**价格序列；ETF 分红已在复权中处理，不构成额外缺口 |
| 数据陈旧 | 由上游 `guard_production_date` 负责；本读数自身不做陈旧判断 |
| `excessPct` 的基准缺失 | 输出 null，**不用 0 填充** |

## 7. 明确不含（防止后被加回去）

本读数**不输出**以下任何东西，将来也不应被加上：

- ❌ 任何 action / buy / sell / entry / exit / score / rank 字段
- ❌ 「是否见底」「是否反弹」「是否值得关注」的判断位
- ❌ 目标价、预期涨幅、概率估计
- ❌ 与其他读数的合成后的综合评分
- ❌ 「触发 → 后 N 日 → 涨了 X%」的回测结论（回测结论留在**存档研究**里，
  不随读数下发——否则下游会当成可用条件）

## 8. 参考实现

`drawdown_readout.py`（同目录）提供纯函数 `compute_drawdown(...)`，
**无副作用、不写文件、不依赖项目内其他模块**，可直接被 generate 类脚本 import。

```python
from drawdown_readout import compute_drawdown
payload = compute_drawdown(dates, closes, volumes, bench_dates, bench_closes)  # -> dict
```

返回结构即 §4 的字段表。Uni test 由接入方自行补。

### 参考实现的第二个坑（基准区间错位）

`compute_drawdown` 的 `bench_dates/bench_closes` 通常比目标序列**长**（基准是全量历史，
目标可能被截断到某一天）。内部必须把基准终点对齐到**目标序列的最后一根日期**：

```python
# ❌ 错：cu = len(bd) - 1          -> 会算到基准的最后一天
# ✅ 对：取 bd 中 <= asOf 的最后一根
```

踩过的后果：创业板 2026-07-30 的 `marketRetPct` 被算成 −5.45%（错），
正确值是 **−6.33%**。差 0.88pp，且 `excessPct` 跟着错。
